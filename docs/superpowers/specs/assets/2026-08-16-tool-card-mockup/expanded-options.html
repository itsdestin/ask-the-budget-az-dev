Expanded tool card — what the assistant did, and what it found

Three ways to rebuild the expanded card, plus a fix for the magnifier. Everything is drawn with the app's real colours, type sizes and spacing, using the actual data the card already receives — nothing here needs new information from the server.

First, the magnifier broken today

The tool card draws its own hand-made magnifier out of six tiny rectangles on a 12×12 grid. At actual size the ring closes into a blob — that smudge in your screenshot is the icon. Meanwhile the app already has a magnifier, used in four places on Home and Budget Documents, and it is the one from the approved design mockup. The tool card is the only place in the app drawing a different one.

What the card shows today current

Struck-through items below are things a fiscal analyst can neither use nor act on.

  • Nothing says what happened or why. The card opens straight into machinery.
  • The numbers are meaningless and quietly misleading. score 1.260 is a raw model score on a roughly −10 to 10 scale — not a percentage, not a confidence. Budget Documents already removed its relevance number and bar for exactly this reason; the ranking is carried by the order.
  • The same text appears twice per result. The grey breadcrumb and the first two lines of the passage are the same words, so ~3 lines of every result are a repeat.
  • The two results look identical. Same document, same section, same opening lines — only the page number differs, and it is the least prominent thing on the row.
  • Raw field names leak. DOC_TYPE: AFR, chunks, bm25 / dense / fused.

A — Same list, decluttered lowest risk

Keeps one row per passage. Removes the scores, the rank numbers and the pipeline counters; translates the filters into English; strips the repeated heading out of the passage text; shows only the last part of the section path instead of the whole breadcrumb. One plain sentence at the top says what was done.

B — Grouped by document recommended

The unit becomes the document, not the passage — which is how an analyst thinks about a source. Five near-identical rows collapse into two blocks; the pages become chips you can see at a glance, and only the best passage from each document shows its text. This is the option that actually answers “what did it look at?” in one glance.

C — Evidence first most readable, least scannable

Leads with the passage text, since that is the only part an analyst actually reads, and puts the source underneath as an attribution line — the shape of a quotation. The section breadcrumb disappears entirely. Reads beautifully for one or two results and gets long fast for five.

What each one costs to build

  • All three are changes inside one file, RetrieveView.tsx, plus a few style rules. None needs anything new from the server — every field shown already arrives with the result.
  • The repeated-heading fix is the same work in all three: the passage text begins with its own section heading, so strip that prefix when it matches. Worth doing whichever option you pick.
  • Turning DOC_TYPE: AFR into “Annual Financial Reports” needs a small lookup. The app already publishes one at /api/document-types, so this is wiring, not new data.
  • B additionally groups passages by document and picks the best one per document to show — about fifteen lines of grouping.
  • Dropping the scores follows what Budget Documents already did. The order still carries the ranking.
